# Oxide — conventions for agents and contributors

Read `PLAN.md` (what to build, phase by phase) and `PROGRESS.md` (where we are) before changing anything.

## Clean-room rule
Oxide recreates the Claude desktop app's features and look from **visible behavior and public specs only**.
Never copy Anthropic code, assets, icons, fonts or UI copy. Use Oxide's own logo and the bundled open fonts.

## Layout
| Path | Owns |
|---|---|
| `src-tauri/` | Thin app crate: windows, tray, Tauri commands/events, plugin wiring. No business logic. |
| `crates/oxide-core` | Domain types only. No I/O, no Tauri. |
| `crates/oxide-store` | SQLite (sqlx) repositories and migrations. |
| `crates/oxide-llm` | `Provider` trait, Anthropic + OpenAI-compatible clients, streaming events. |
| `crates/oxide-mcp` | MCP client: transports, protocol, server manager, `.mcpb`. |
| `crates/oxide-agent` | Reply generation (`ChatService`, `ModelRegistry`), agent loop, tool registry, approvals, built-in tools. Emits through the `EventSink` trait; no Tauri. |
| `crates/oxide-bridge` | Chrome extension WebSocket bridge. |
| `crates/oxide-pyenv` | uv bootstrap, venv, Python sidecars. |
| `crates/oxide-sandbox` | Docker sandbox: per-chat workspace containers, commands, copies, the per-chat filesystem MCP server (Phase 12b). |
| `crates/oxide-computer` | Screen capture + input. |
| `src/` | React + TypeScript frontend. |
| `src/bindings/` | **Generated by tauri-specta. Never edit by hand.** Regenerate with `npm run bindings`. |
| `python/` | Python packages run in the managed venv (Phase 12+). |
| `extension/` | MV3 Chrome extension (Phase 14). |
| `.github/workflows/` | CI (checks on Windows, macOS, Linux) and the release matrix (Phase 17; see `docs/RELEASING.md`). |

Library crates must not depend on `tauri`. Only `src-tauri` does.

## Rust rules
- Edition 2024, toolchain pinned in `rust-toolchain.toml`.
- No `unwrap()` outside tests (clippy denies it). `expect()` only with a message that explains the invariant.
- Errors: `thiserror` enums in library crates, `anyhow` only in `src-tauri`.
- Commands return `Result<T, E>` where `E: Serialize + specta::Type` once they can fail.
- Logging with `tracing`. Never log API keys, tokens, or message content at info level or above.
- Async with `tokio`. No blocking I/O on the async runtime; use `spawn_blocking`.
- `unsafe` is denied workspace-wide; a crate that needs it (e.g. Windows APIs) opts in locally with a comment explaining why.
- Every new Tauri command: `#[tauri::command] #[specta::specta]`, registered in `collect_commands!`, then regenerate bindings.
- Commands are permission-checked per window (Phase 17): add `allow-<command-with-dashes>` to `src-tauri/capabilities/default.json` (the main window), and to `quick.json` / `computer.json` only if that window calls it. `src-tauri/src/acl.rs` tests fail when they drift. Frontends call plugins only through Oxide's own commands.

## Frontend rules
- React 18+, TypeScript strict, function components and hooks only.
- Import via the `@/` alias. Folders: `app/` (shell, routes, providers), `components/` (shared UI), `features/<name>/` (feature code), `styles/`, `bindings/` (generated).
- Styling: Tailwind v4 utilities backed by CSS variables in `styles/tokens.css`. No hard-coded colors in components.
- Backend calls only through `@/bindings` (`commands.*`, `events.*`). Never call `invoke` with string names.
  Core window/webview APIs (`@tauri-apps/api/window`, `/webview`) are allowed, but only via the wrappers in `src/lib/window.ts`.
- Colours, radii, shadows and fonts come from `--ox-*` tokens (`styles/tokens.css`), used through Tailwind names like `bg-app`, `text-fg-muted` and `border-line`.
- Tests render the app with `renderApp()` (`src/test/renderApp.tsx`), which uses `MemoryRouter`. Data routers break under jsdom on Node 26 (AbortSignal mismatch).
- State: Zustand for UI state, TanStack Query for backend data (from Phase 2).
- Streaming replies arrive as typed events (`events.chatStream`). One app-wide listener (`features/chat/useChatEvents.ts`) feeds the Zustand store in `features/chat/streams.ts`; saved replies go into the query cache.
- The test fake (`src/test/fakeBackend.ts`) streams replies through `fakeEvents`. Use `renderApp(path, { backend: { replies: "hold" } })` with `finishReply()` to test a reply mid-stream.

## Checks (must pass before a phase is done)
```
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
npm run typecheck
npm run lint
npm test
cargo tauri dev        # manual check against the phase's exit criteria
```

## Build environments
- Windows is the primary dev machine (`C:\AI Apps\Oxide`). Run npm, cargo and `cargo tauri dev` in PowerShell.
- Never share `node_modules/` or `target/` between Linux and Windows. Linux-side checks use `CARGO_TARGET_DIR=$HOME/oxide-target-linux`.

## Git
- One commit per phase at minimum: `phase N: <title>`. Smaller commits inside a phase are fine.
- Generated bindings and icons are committed; `target/`, `node_modules/`, `dist/` and sidecar binaries are not.
